<objective>
Tag real catalog items and prove the catalog kept exactly what was written, twice.

Purpose: DAM-02. The product's "Verify Daminion writes" helper is the read-back, and it is wrong on the
server shape this phase runs against, so it is fixed and pinned before it is trusted.
</objective>

<tasks>

1. Fix `VerifyItemMetadataAsync` to read `TagPairsFromItemData` (propertyName → value, multi-value
   arrays expanded) instead of `CollectKeyValuePairs` (JSON member names). Keep the tolerant matching;
   add a test built from the recorded 11.x payload in `DaminionCaptureDateTests`.
2. Live test: fetch up to 25 items from saved search 16 with the untagged filter for all three fields;
   fail loudly if fewer than 5 are available (a skip means the scope is exhausted, and the reason says so).
3. Run them through `PipelineHarness` with a live `DaminionApiClient` and a deterministic sidecar whose
   tags carry a run marker (`synapic-live-<date>` keyword, a fixed category and a description naming the
   item id). Assert every row `Completed` and `IsPaused` false.
4. Read back: `VerifyItemMetadataAsync` for each item plus a direct `TagPairsFromItemData` assertion that
   the keyword set, category and description are exactly the written values (no extras in the written
   keyword).
5. Re-run the same ids through a fresh queue and executor; read back and assert each written keyword
   appears exactly once and the field values are unchanged.

</tasks>
