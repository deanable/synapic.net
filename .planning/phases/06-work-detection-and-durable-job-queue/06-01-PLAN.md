  <action>
    `QueueSchema` owns the DDL: `PRAGMA journal_mode=WAL`, `PRAGMA user_version=1`, `CREATE TABLE IF NOT EXISTS
    jobs(...)` exactly as the CONTEXT lists with `key TEXT NOT NULL COLLATE NOCASE UNIQUE` and defaults
    (`attempts 0`, timestamps NOT NULL), `CREATE TABLE IF NOT EXISTS job_events(id INTEGER PK, job_id INTEGER NOT
    NULL REFERENCES jobs(id), at TEXT NOT NULL, from_state TEXT, to_state TEXT, detail TEXT)`, and
    `CREATE INDEX IF NOT EXISTS ix_jobs_state ON jobs(state)`. `EnsureAsync(SqliteConnection)` is idempotent —
    the service runs it on every start and a second run must not throw or lose rows.
    `IndexingQueueRepository(string databasePath, TimeProvider? clock = null)`:
    - connection factory sets `busy_timeout=5000` on every opened connection; writes go through
      `SemaphoreSlim(1,1)` and `BEGIN IMMEDIATE`, reads use their own short-lived connection;
    - `InitializeAsync()` creates the schema;
    - `GetByKeyAsync(key)`, `GetAsync(id)`;
    - `EnqueueAsync(IReadOnlyList<JobCandidate> candidates)` → `IntakeResult {Enqueued, Skipped, EnqueuedKeys}`
      applying the matrix in one transaction; it computes no fingerprints and takes the candidate's size/mtime/hash
      as given. On "Completed changed" it resets `attempts` to 0 and writes the transition event; on
      "Completed unchanged hash, mtime moved" it updates `mtime_utc`/`updated_at` and returns Skipped;
    - `ClaimBatchAsync(int max, ct)` → `IReadOnlyList<JobRecord>`: inside BEGIN IMMEDIATE select Pending rows with
      `next_attempt_at IS NULL OR next_attempt_at <= now` ordered by `id ASC` limited to max, transition each to
      InFlight with `attempts = attempts + 1`, commit once;
    - `MarkCompletedAsync(id, detail?)`, `MarkTransientAsync(id, error, retryAt)`,
      `MarkFailedAsync(id, error)`, each validating through `JobStateMachine` and writing a job_events row with the
      error text truncated to 1000 chars;
    - `RecoverInFlightAsync()` → int, one transactional `UPDATE ... WHERE state='InFlight'` plus one event row per
      affected job with detail `"service restart"`;
    - `GetSummaryAsync()` → `QueueSummary {Pending, InFlight, Completed, TransientFailure, Failed,
      RecentFailures}` where `RecentFailures` is the five newest Failed/TransientFailure rows by `updated_at DESC`
      (`id, key, last_error`);
    - `GetActivityAsync()` → `(bool HasPendingWork, DateTime? LastWorkAt)`: pending means any
      Pending/InFlight/TransientFailure row; LastWorkAt is the newest `updated_at` among them (D-11-18);
    - `OpenReadOnly(path)` static helper used by `--status`: `Mode=ReadOnly`, returns null when the file does not
      exist. All SQL is parameterized; no string concatenation of paths or errors.
    Timestamps are stored as round-trip UTC (`"o"`); in-memory `DateTime` values are `DateTimeKind.Utc`.
  </action>
