  <action>
    `DebounceBuffer(TimeSpan window, TimeProvider clock)`: `Add(path)` records `due = clock.GetUtcNow() + window`
    and overwrites any previous due for that key; `DrainReady()` returns and removes keys whose due is past;
    `ReArm(path, delay)` re-adds with an explicit due and an attempt count. Thread-safe (watcher callbacks arrive
    on thread-pool threads). `FileStabilityProbe.TryOpenExclusive(path)` opens
    `FileStream(path, FileMode.Open, FileAccess.Read, FileShare.None)` and returns true only when the open
    succeeds; it never throws for a locked/missing file (returns false + reason). Tests for the buffer use a fake
    clock: duplicate events extend the window, two paths release independently, `ReArm` respects its own delay.
    Probe tests: hold a lock with a `FileStream(FileShare.Read)` and assert false; release and assert true; assert
    a deleted file returns false rather than throwing.
  </action>
  <verify>dotnet test tests/Synapic.Indexer.Tests -c Release --nologo --filter "FullyQualifiedName~DebounceBufferTests|FullyQualifiedName~FileStabilityProbeTests" → exit 0</verify>
  <acceptance_criteria>
    - Debounce behavior is proven without sleeping
    - Probe never throws for ordinary filesystem races
    - Buffer is safe under concurrent Add/Drain
  </acceptance_criteria>
  <done>The timing rules are testable in isolation</done>
