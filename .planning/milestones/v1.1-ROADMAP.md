# Milestone v1.1: Windows Indexer Service

**Status:** ✅ SHIPPED 2026-10-23
**Phases:** 4–8
**Total Plans:** 19
**Requirements:** 31/31 complete (CORE-01..04, HOST-01..07, SCAN-01..07, TAG-01..08, OPS-01..05)
**Source spec:** `docs/windows-indexer.md` v1.0.0

## Overview

The unattended half of the product: `Synapic.Indexer.exe`, a Windows Service that tags images on a
schedule and on filesystem events, writes the tags back to files or a Daminion catalog, and recovers
from crashes and reboots — running the same engine as the desktop app.

Phase 4 lifted the engine out of the Avalonia project into an Avalonia-free `Synapic.Core`. Phase 5
stood up the service host and its schema-versioned configuration. Phase 6 gave it work: interval
scans, a debounced filesystem watcher and Daminion untagged queries feeding one durable SQLite
queue. Phase 7 drove that queue through the shared `ProcessingOrchestrator` kernel with write-back
policy and the spec's failure table. Phase 8 made it shippable and proved it unattended: installer
payload, ProgramData ACLs, operator documentation, and an end-to-end acceptance run on a real
install → tag → stop → crash-recover → uninstall cycle.

**Scope fence:** tagging only. Background dedup and upscaling were deferred to a later milestone
(BG-01/BG-02).

## Phases

### Phase 4: Extract headless engine core

**Goal**: Create `src/Synapic.Core` (net10.0, no Avalonia) and move the engine services into it —
`InferenceApiClient`, `InferenceSidecarService`/`IInferenceSidecar`, `MetadataWriterService`/`IMetadataWriter`,
`DaminionApiClient` and its request models, and the tagging kernel (`WorkflowRunner`, `ProcessingOrchestrator`,
`DatasourceSelection`, `ProcessWorkItem`, `ProcessResult`, `PauseToken`, `ProcessStatus`). Replace the sidecar
host's dependency on the UI `Session` with an injected device provider, move the Serilog facade so both hosts
can initialize it, and repoint `Synapic.Main` at the library with zero behavior change. Add
`tests/Synapic.Core.Tests` and move the service-only tests that need no Avalonia host.
**Depends on**: Phase 3 (source tree stable; the UI refactor's Services scope freeze ends here)

- [x] `04-03` — Move the tagging kernel and repoint `Synapic.Main` (namespaces, DI, test references) — Main baseline 738 passed / 3 skipped recorded
- [x] `04-04` — Add `Synapic.Core.Tests`, move the service-only tests, and run the phase gate sweep — Core 144, solution 756 cases, 0 tests deleted, Release 0/0, no Avalonia/Main in Core's deps

**Details:**

### Phase 5: Indexer service host and configuration

**Goal**: Stand up `src/Synapic.Indexer` as a `Microsoft.Extensions.Hosting` Windows Service. Implement the
schema-versioned configuration (registry `HKLM\SOFTWARE\Synapic\Indexer` +
`%ProgramData%\Synapic\indexer-config.json` override) with fail-fast validation and actionable startup errors;

up an orphan on exit); and the `--install` / `--uninstall` / `--console` control surface including the recovery
actions from the spec.

### Phase 6: Work detection and durable job queue

**Goal**: Give the service work. Implement the SQLite job queue with its five states and crash recovery, the
interval scan of configured local roots with change detection, the debounced `FileSystemWatcher` with an
exclusive-read probe, and the Daminion untagged-scope query. Enqueueing must be idempotent and must never
double-process an item that is already queued or completed unchanged.
**Depends on**: Phase 5
**Plans**: 4 plans

Plans:

- [x] `06-01` — SQLite job store: schema, state machine, idempotent enqueue and startup recovery
- [x] `06-02` — Local interval scan + change/hash detection
- [x] `06-03` — Filesystem watcher, debounce buffer and file-stability probe
- [x] `06-04` — Daminion untagged-scope source, `--status` reporting, and the phase gate

**Details:**
SCAN-01..07 ✓ — acceptance transcript beside `06-04-SUMMARY.md`. A console run scanned a fixture
(found 3, enqueued 3), a dropped file was enqueued once after the 5 s debounce, the next tick found all
four already queued, a forced kill plus a seeded `InFlight` row recovered on restart (`InFlight →
Pending`, detail `service restart`) with no duplicates, and `--status` printed the counts while the
service ran and after it stopped. Suite: Shared 6, Core 144, Indexer 175, Main 598 passed / 3 skipped
(**923** cases); Release 0/0.

Stated limit: no executor existed until Phase 7, so the mid-batch kill was seeded rather than observed
(repeated with a live batch in 07-03 and 08-03). The Daminion path is proven against a fake fetch seam,
not a live catalog.

Cross-cutting constraints: the queue is the single source of truth for work — the scheduler never keeps
in-memory-only jobs; paths are canonicalized before enqueueing so one file cannot enter twice under
different casing.

### Phase 7: Tagging pipeline and write-back

**Goal**: Turn queue rows into tagged images through the shared kernel. Build the `TagRequest` and
`TagFieldSelection` from configuration, run batches via `ProcessingOrchestrator` at the configured concurrency,
map per-item outcomes to queue states, honour the per-field switches and `overwriteExistingTags`, and add the
resilience layer the spec's failure table requires: sidecar restart with backoff, locked-file transient retry,
Daminion outage pause/retry, corrupt-file permanent failure. Finish with a parity harness that runs the same
image through the desktop kernel and the indexer path.
**Depends on**: Phase 6
**Plans**: 4 plans

Plans:

- [x] `07-01` — Batch executor over `ProcessingOrchestrator`: request construction, concurrency, outcome → job-state mapping
- [x] `07-02` — Write-back policy: field switches, overwrite/merge semantics, existing-tag preservation
- [x] `07-03` — Resilience: sidecar restart/backoff, transient lock retry, Daminion pause/retry, permanent failure classification
- [x] `07-04` — Parity harness (indexer kernel vs desktop kernel), run diagnostics, and the phase gate

**Details:**
TAG-01..08 ✓ — the five criteria and the requirement matrix are in `07-04-SUMMARY.md`. Batch execution,
the write-back policy, the §8 failure table and the parity harness are covered by 26 new Indexer facts
plus 4 in Core. The **real mid-batch kill** was observed, not seeded: the production
`InferenceSidecarService` launched `artifacts/win-x64/synapic-inference.exe`, the process was killed
during the first in-flight `/tag` (pid 45304), the supervisor restarted it (pid 44804) and all six rows
reached `Completed` with the tags on disk (`RealSidecarKillTests`, opt-in via `SYNAPIC_TEST_REAL_KILL=1`
because it loads the model twice).

Suite at the gate: Shared 6, Core 148, Integration 5, Indexer 213 passed / 1 skipped. Release 0/0.
Main.Tests was not green on the gate machine and was recorded as a limitation, not a pass.

Deferred explicitly: repeating parity with the live model (not the deterministic fake) became 08-03's
observation; a live Daminion server returning mid-pause likewise. `overwriteExistingTags:true` still means
"write the model's values", not "delete existing keywords" (merge-only, pinned by a test).

Cross-cutting constraints: the indexer must not fork the tagging logic — every inference/metadata call
goes through `Synapic.Core`; a retry never re-runs a completed write or duplicates Daminion tags.

## Milestone Summary

**Decimal Phases:** none (Phases 4–8 ran in order with no urgent insertions).

**Key Decisions:**

- **D-11-01: `Synapic.Core` is a new headless library, not a reference to `Synapic.Main`.** A LocalService
  process must not load the desktop UI stack. Rejected: referencing `Synapic.Main` (drags Avalonia in) and
  duplicating services (guarantees parity drift).
- **D-11-02: The indexer reuses `ProcessingOrchestrator`, not just the sidecar client.** Parity is a property
  of not forking the download → `/tag` → write path.
- **D-11-03: The sidecar's `Session` coupling is replaced by `ISidecarDeviceProvider`**, with `Synapic.Main`
  supplying an adapter over `Session`.
- **D-11-04: Logging moves to Core as the Serilog facade it already is**; the service initializes it with its
  own directory, level and Event Log sink and never shares the desktop log file.
- **D-11-05: Configuration is schema-versioned and validated once at startup**; invalid config fails startup
  naming the key. A service that silently guesses is worse than one that refuses.
- **D-11-06: The job queue is SQLite and the only source of truth for work**; `InFlight` on startup is a crash
  recovery, not an option.
- **D-11-07: Daminion credentials in `indexer-config.json` use DPAPI at LocalMachine scope**, written by
  `--set-daminion-password`. Trade-off accepted and documented: any local administrator can decrypt it.
- **D-11-08: The Event Log source is created at install time, not at first run**, because creating a source
  needs administrator rights the service account may not have.
- **D-11-23: `overwriteExistingTags:false` skips a fully tagged file** with no `/tag` call and merges only the
  empty selected fields otherwise; keywords are never deleted — overwrite means "write the model's values".
- **D-11-28/29: The packaging build publishes the indexer after the app and fails by name** if
  `Synapic.Indexer.exe`, `Synapic.Core.dll` or `synapic-inference.exe` is missing.
- **D-11-31: Both installer channels carry the same payload; the Inno EXE is the shipping channel** and
  registers the service through `--install`; the MSI ships files and documents the one elevated command.

**Issues Resolved:**

- The service was being registered as LocalSystem while the spec and docs promised LocalService — found only by
  the acceptance install, fixed with an explicit `obj=` token and pinned by a test.
- A failed `--install` start was invisible to the installer because `[Run]` discards exit codes — the indexer
  install moved into `CurStepChanged` with the code logged and named on the finish page.
- A dead sidecar originally classified as `PauseRun` (a five-minute pause) — the classifier was corrected so the
  sidecar's process state outranks `HttpRequestException`; a catalog download failure pauses the run.
- `--status` created directories and a log file before the queue existed — the command now runs before
  `EnsureCreated()` and writes nothing.

**Issues Deferred:**

- **The MSI channel was not built or exercised** (WiX absent on the gate machine); only the Inno path was
  verified. The MSI is stated as not exercised, not as passed.
- **Daminion ran against fake network seams, not a live catalog**; a server returning mid-pause is unproven.
- **Parity used the desktop's kernel** with the real model, not the GUI — `Synapic.Main.exe` has no headless
  processing entry point.
- **A fresh install ends stopped** until `indexer-config.json` exists; the finish page and docs say so.
- **`Synapic.Main` UI keeps its own operation paths** (dedup/upscale) untouched by this milestone; only the
  tagging engine is shared.

**Technical Debt Incurred:**

- The default parallel solution test run is unstable in this environment (one differing Avalonia UI test per
  run, each passing alone); gates record `-m:1` results.
- `RealSidecarKillTests` is opt-in (`SYNAPIC_TEST_REAL_KILL=1`) because it loads the model twice, so the
  live-kill path is not in the default suite.
- The compiled help corpus still names the old wizard steps (`HelpTopics.ForStepIndex` maps 0–5) — a docs pass,
  carried from v1.0.
- `overwriteExistingTags:true` merges rather than replacing keywords; the semantic gap is pinned by a test but
  remains a documented limitation.
- Acceptance residue is deliberate: `%ProgramData%\Synapic` (config, logs, 45 KB queue) and
  `C:\ProgramData\Synapic-Acceptance\watch` with 21 tagged fixtures remain on the dev machine.
