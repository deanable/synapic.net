## v1.1 Requirements

### Shared engine core (CORE)

- [x] **CORE-01**: `Synapic.Core` is a headless `net10.0` class library in the solution that contains the inference client, sidecar host, metadata writer, Daminion client and the tagging kernel, and references **no** Avalonia, `Synapic.Main`, or view-model assembly
- [x] **CORE-02**: `Synapic.Main` consumes those services from `Synapic.Core` through their existing interfaces, with no user-visible behavior change (the full desktop suite stays green)
- [x] **CORE-03**: The sidecar host obtains its compute device and launch directory from injected abstractions instead of the UI `Session`/`SynapicLog` statics, so a non-desktop host can drive it
- [x] **CORE-04**: A headless `Synapic.Core.Tests` project exercises the moved services without an Avalonia test host, and the service-only test files that do not need the UI are moved into it

### Service host and configuration (HOST)

- [x] **HOST-01**: `Synapic.Indexer.exe` installs and starts as a Windows Service (`Microsoft.Extensions.Hosting.WindowsServices`) with no signed-in user and no interactive desktop session
- [x] **HOST-02**: The indexer reads configuration from `HKLM\SOFTWARE\Synapic\Indexer`, with `%ProgramData%\Synapic\indexer-config.json` overriding it when present
- [x] **HOST-03**: Configuration is schema-versioned and validated at startup; invalid values (unknown mode, interval out of 1 min–24 h, missing credential, unwritable paths) fail startup with an actionable Event Log + log-file error instead of a stack trace
- [x] **HOST-04**: The service starts the bundled `synapic-inference.exe --port=0`, polls `/health` until ready, and stops an idle sidecar after the configured timeout
- [x] **HOST-05**: Logging is Serilog with an Event Log sink under source `SynapicIndexer` and a rolling file sink at `%ProgramData%\Synapic\Logs\indexer-YYYYMMDD.log` with 30-day retention
- [x] **HOST-06**: `sc.exe stop` or a system shutdown completes within 10 seconds, cancels in-flight work, and leaves no orphaned `synapic-inference.exe`
- [x] **HOST-07**: `Synapic.Indexer.exe --install`, `--uninstall` and `--console` work from an elevated prompt: install registers the service (auto start + restart-on-failure recovery), uninstall removes it, and console mode runs the same host interactively for diagnosis

### Work detection and durable queue (SCAN)

- [x] **SCAN-01**: On each interval tick the indexer walks the configured local roots recursively for `.jpg/.jpeg/.png/.tif/.tiff` and enqueues candidates
- [x] **SCAN-02**: A file is not enqueued when a completed job already records it at the same size, last-write time and content hash; a changed file is enqueued again
- [x] **SCAN-03**: In watch mode a `FileSystemWatcher` accumulates create/change/rename events over a configurable debounce window (default 5 s) and only enqueues a file after it passes an exclusive-read probe
- [x] **SCAN-04**: In Daminion mode the indexer queries the configured catalog scope for items whose selected untagged fields (`keywords`, `categories`) are empty and maps them to queue jobs
- [x] **SCAN-05**: The job queue persists in SQLite with explicit `Pending`, `InFlight`, `Completed`, `TransientFailure` and `Failed` states, and survives a service restart
- [x] **SCAN-06**: On startup every job left `InFlight` by a crash or reboot is returned to `Pending`, and the batch continues without losing or duplicating a completed item
- [x] **SCAN-07**: Enqueueing is idempotent — the same path/scope item cannot appear twice in the queue at once, and a `Completed` item is not re-enqueued unless it changed

### Tagging pipeline and write-back (TAG)

- [x] **TAG-01**: A batch runs through the shared `ProcessingOrchestrator` kernel with the configured concurrency (`maxConcurrentItems`, default 4) and the configured model/confidence/probability/prompt parameters
- [x] **TAG-02**: Local files receive category, keywords and description through `IMetadataWriter`, honouring the per-field write switches and `overwriteExistingTags` (false preserves tags already present on the file)
- [x] **TAG-03**: Daminion items are tagged by downloading the image, calling `/tag`, and checking the tags back in through the configured catalog client
- [x] **TAG-04**: For the same image and the same engine parameters, the tags produced by the indexer equal those produced by `Synapic.Main` (automated parity check)
- [x] **TAG-05**: A sidecar crash or OOM is detected, the sidecar is restarted with exponential backoff (max 3 attempts per batch), and the interrupted batch resumes
- [x] **TAG-06**: A file locked by another process becomes `TransientFailure` and is re-queued after 60 seconds rather than failing the batch
- [x] **TAG-07**: When the Daminion server is unreachable the run pauses and retries the connection every 5 minutes until it returns, without dropping queued items
- [x] **TAG-08**: A corrupt/undecodable image is recorded `Failed` with its error detail and the batch continues; no item is ever silently lost

### Deployment, docs and acceptance (OPS)

- [x] **OPS-01**: The Windows packaging build ships `Synapic.Indexer.exe` and the sidecar in the installer payload, creates `%ProgramData%\Synapic` with ACLs the service account can write, and registers the Event Log source
- [x] **OPS-02**: An unattended acceptance run tags an image dropped into a watched folder and the tags are visible in the file/catalog, with no desktop session and no user interaction
- [x] **OPS-03**: The acceptance run proves clean stop (`sc stop` within 10 s, no orphan sidecar), reboot recovery (no lost `InFlight` job) and parity with a desktop run
- [x] **OPS-04**: Documentation covers install/uninstall, the full configuration reference, log locations and the five failure modes in `docs/windows-indexer.md` §8
- [x] **OPS-05**: `dotnet build Synapic.Net.sln` is 0 warnings/0 errors and the whole solution suite (Shared + Core + Main + Integration) is green at the phase gate, with no test weakened or skipped

## v2 Requirements (deferred, not in this milestone)

- **BG-01**: Background deduplication runs on the same scheduler and job queue
- **BG-02**: Background upscaling runs on the same scheduler and job queue
- **UI-01**: An in-app surface to view indexer status/history from `Synapic.Main`
- **DIST-01**: Indexer self-update alongside the app's update check

## Out of Scope

| Feature | Reason |
|---------|--------|
| Background dedup / upscale operations | Spec lists them as optional; milestone scoped "tagging only" by the user. Deferred to v1.2 (BG-01/02) |
| Remote/central management API | Not in the spec; a local service only |
| Multi-tenant or per-user queueing | A single machine-wide service account owns the queue |
| Linux/macOS service hosts | Spec targets Windows 10/11 and Server 2019+; the existing app stays cross-platform |
| Reworking the desktop UI for indexer control | Parity and headless operation are the goal; a UI surface is UI-01/v2 |
| Replacing the Python sidecar or its models | The sidecar is reused unchanged |
