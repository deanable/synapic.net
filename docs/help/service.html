The background service

Synapic can tag images with nobody at the desk. A Windows service — SynapicIndexer — watches folders you choose, queues every file that lands in them, and runs the same tagging engine the app uses. The model's keywords and description are written into each image file, which is what lets Windows itself index and search them.

Everything lives on the Service tab of Settings.

Open Settings and pick the Service tab. It has three parts: the service itself (install, start, stop, uninstall), the folders it watches, and the queue showing what is waiting, running, done or failed.

Installing and controlling the service

The service is normally installed by the Windows installer. The tab can do the same by hand: Install registers SynapicIndexer to run as the low-privilege LocalService account, start automatically at boot, and restart itself if it fails. Start and Stop control it, Uninstall removes it — logs and data under %ProgramData%\Synapic are kept.

Each of these asks Windows for permission once (a UAC prompt), because registering and controlling a service is an administrator's act. The tab itself only ever reads the service state — that needs no permission.

Watch folders

A watch folder is a directory the service monitors: when an image file lands in it — copied in, saved by a camera import, produced by another tool — the file is fingerprinted, queued, and tagged when its turn comes. Subfolders can be included or ignored.

Detection has three modes: watching the folders only, scanning them on an interval, or both. Watching reacts the moment a file is stable; the interval scan also catches files that arrived while nothing was watching.

Saving asks for permission once. The change is validated before it is saved — a folder that does not exist is refused rather than silently breaking the service — and the service is restarted if it was running, because it reads its configuration at startup.

The queue

Every file is one durable queue row: Pending (waiting), In flight (being tagged), Completed, Retrying (a transient problem — a locked file, a server pause — will be tried again) or Failed. The counts refresh while the tab is open; recent failures show their error, and the activity list is the service's history.

The queue lives in %ProgramData%\Synapic\state\indexer.db and survives restarts: work that was in flight when the machine stopped is picked up again when it starts. Nothing in it is deleted — completed rows are the record of what the service has done.

See also the Settings reference and how a run works — the service runs the same engine, the same model and the same write-back rules the app's tagging view uses.
