What gets written to your images

Synapic writes standard XMP metadata, in the properties other applications already understand. For a folder, into the files; for Daminion, through the catalog's own API.

The three fields, and where they land

Tag fieldFile metadataDaminion
Categoryphotoshop:Headline, plus Iptc4xmpCore:IntellectualGenreThe item's Categories tag
Keywordsdc:subject (a bag of subjects)The item's Keywords tag
Descriptiondc:description, as the x-default alternativeThe item's Description

Choosing standard properties is deliberate: Adobe Bridge, Lightroom, Windows Explorer, Daminion and most DAM importers already show dc:subject as keywords and dc:description as the description, so a tagged folder means the same thing everywhere.

By file type

FormatHow it is written
JPEG (.jpg, .jpeg)The existing XMP packet is patched, or a new one inserted as an APP1 segment through a staged file. The image is not re-encoded, so the pixels are untouched and the file does not lose quality.
PNG (.png)The Adobe XMP international-text chunk (iTXt) is patched and replaced, or inserted after the header if absent. Repeated updates do not add duplicate XMP chunks. Like the JPEG path, the image data is left alone.
TIFF (.tif, .tiff)An adjacent sidecar named image.tif.xmp (or image.tiff.xmp) is patched and read back by Synapic. Other applications must support this sidecar naming convention. The tags are therefore not inside the TIFF itself — if you copy the image somewhere, copy the sidecar too, or the tags will not follow.
Daminion itemsWritten back through the catalog's item-update API. No files on disk are touched by Synapic at all in this mode.

What happens to values that were already there

  • Folder runs patch selected fields. Nonempty category and description values replace the selected headline/genre and default description. Keywords merge with the existing list, without duplicate values. Unticked fields and empty model values leave the existing metadata unchanged. Description translations and unrelated XMP properties are preserved. This file policy does not change the Daminion catalog API's existing behavior.
  • Untouched everywhere else. Synapic does not write other XMP properties, EXIF, IPTC or filename fields. Your camera data, ratings, copyright and existing non-keyword metadata stay as they were.
  • Two writers, one truth. A folder run writes files, not a catalog, so Daminion will only see those tags when it re-reads the files. In Daminion mode the writing happens the other way round. Pick the mode that matches where the metadata is authoritative for you.

Keep a backup before the first big run.

There is no undo for successful changes. Selected category and description values can replace previous values; new keywords are added. Copy a sample, or the whole set, until you trust the settings. TIFF sidecars must stay with their images; sidecar-aware duplicate move/delete actions are not yet implemented.

Reading it back

Synapic reads its file XMP properties and TIFF sidecars, plus IPTC and EXIF fallbacks for images tagged by other tools. File round-trip tests check preservation as well as the new values. Verify Daminion Writes separately re-reads the catalog through its API; it does not use the file metadata reader.

Safe writes and supported limits

Changed metadata is streamed into a unique temporary file in the same folder, validated as XMP and decoded as an image, then atomically replaces the destination. Failed writes or cancellation before commit leave the prior artifact untouched. Cancellation after a completed commit cannot undo the write. The folder needs space for a staged copy and permission to replace files; read-only files and symbolic links are refused. TIFF pixels are never rewritten.

Basic JPEG XMP must fit the APP1 segment's 65,535-byte length, including its header. Oversized, malformed, multiple or extended XMP packets are rejected rather than silently discarded. PNG text and TIFF sidecar XMP have a 16 MiB safety limit. Staging is not a multi-file transaction or protection against concurrent external editors; keep backups and avoid editing the same image in two applications.
