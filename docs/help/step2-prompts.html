Prompts: system prompt and tag instruction

Step 2 has two text boxes, and it is easy to confuse them. One sets the context the model works in; the other says what the model must produce. Only the second one can break the result, and you do not need to touch either.

Which box does what

BoxIts jobSafe to leave alone?
System prompt (optional VLM context)Context prepended to every request: tone, vocabulary, language, domain.Yes — blank by default
Tag instruction (sent to the model for every image)The instruction that asks for the result. It is the thing that makes the reply parsable.Yes — blank means the built-in one

The system prompt

The system prompt is prepended to the request, so it colours everything the model says without changing the shape of the answer. Use it for things that stay true across a whole library:

  • Language and spelling. "Write keywords in British English." "Write the description in German."
  • Tone and length. "Descriptions are one sentence, factual, no marketing language."
  • Domain vocabulary. "This is an archive of architectural photography; prefer established architectural terms."
  • Things to avoid. "Never use the word 'image' or 'photo' in the description."

Never ask the system prompt for a different output shape.

Synapic reads a category, a keyword list and a description out of the reply. If the system prompt asks for prose, a different set of keys, or a markdown report, it fights the instruction below it — and that is the one reliable way to make the parser's job hard. Anything the app cannot recognise ends up in the description as raw text. Steer the wording, not the format.

The saved system prompts

The system prompt is the field people iterate on, so the app keeps a history of them rather than one copy. The combobox above the box lists every system prompt you have used, most recent first.

ActionWhat happens
Type a prompt and leave the box (or move off Step 2)It is committed to the history and selected in the list. A blank box is never saved.
Pick an entry from the listIt fills the box.
Highlight an entry and press DeleteThe entry is removed from the history. If it was the prompt in the box, the box is cleared too — otherwise the next commit would simply save it again.
Read the line under the boxConfirms what happened: saved, removed, or that nothing was selected to remove.

The history lives in a small JSON file, %APPDATA%\Synapic\system-prompts.json, newest first and capped in length. It is a convenience list, not the setting: the prompt actually used by a run is stored with the rest of your Step 2 settings, so pruning this list can never change how a batch behaves.

The tag instruction

This is the user_prompt the inference server receives. Blank means use the built-in instruction, which is the default and the version that is tested against the model:

  • Use built-in instruction loads the server's own text into the box, so you can read it or adapt it. It comes from the running server rather than a copy in the app, so the two can never disagree.
  • Reset to built-in clears the box back to blank — which, again, means built-in.
  • An orange Using a custom instruction marker appears whenever the box holds text, so a forgotten experiment is visible.

A custom instruction must keep asking for the same JSON shape.

The built-in instruction asks for a JSON object with the three keys Synapic reads. A custom instruction has to do the same, and be explicit that the keywords are a list of tags. An instruction that merely mentions the three keys can come back with valid JSON and no keywords at all; the server logs a warning when that happens, so check the log if a run suddenly produces empty fields.

Trying prompt changes without wasting a batch

  1. Copy ten representative images into a scratch folder.
  2. Run them with your current settings and note what you think of the output in Step 4.
  3. Change one thing — the system prompt, and only the system prompt.
  4. Run the same ten again and compare. Tags are replaced, not merged, so the second run is the one you judge.

One change at a time, on the same images, is what makes prompt work informative rather than superstitious. If the output degrades and you cannot say why, clear the system prompt and reset the instruction to built-in: that is the configuration the app is tested with.
