Tag fields: what gets written

One model call always produces a category, a set of keywords and a description. The three Tag fields checkboxes decide which of those three are written to your library. This is the setting behind almost every "Synapic only tagged keywords" report, so it is worth a minute.

The three checkboxes

CheckboxWritten as
KeywordsThe keyword list, as a bag of subjects (XMP dc:subject in a file; the Keywords tag in Daminion)
CategoriesThe category, as a headline and intellectual genre in the file, and as the Categories tag in Daminion
DescriptionThe one-line description (XMP dc:description)

All three are ticked by default. At least one must stay ticked or Step 2 refuses to let you continue, with a red Select at least one field to continue.

What a partial selection does

Untick a box and the model still produces that field — it is simply dropped at the write step, before anything reaches your library or catalog. Nothing is logged as skipped: the item is reported as updated like any other.

Because that is invisible after the fact, Synapic says it twice.

On screen, in Step 2

An orange line appears under the checkboxes while the selection is partial, naming exactly what will be written:

Writing keywords only — the model still returns all three fields. Tick the other boxes to tag those too.

It is visible only where the decision is still changeable, which is the point. It disappears the moment all three boxes are ticked again.

In the log, at the start of every batch

The first line of a run states the same thing, so a log file answers the question without the UI:

Starting batch: 42 items — writing keywords only
Batch finished: 42 ok, 0 failed, 42 total

The same summary goes to logs\synapic.log, so a run recorded months ago still says which fields it wrote.

"My items have keywords but no category or description"

Work through this in order. The first two steps find the cause in under a minute, and the third proves it beyond argument.

  1. Look at Step 2. Are all three Tag fields ticked? If the orange warning is on screen, this is the answer.
  2. Look at the batch's first log line. It names the written fields. If it says writing keywords only, the run did exactly what it was told.
  3. Confirm the model is fine. The inference server always returns all three fields; the selection only affects writing. To see that for yourself, tick all three boxes, run one image, and watch the result line name a category and a description like it always did.

Why it persists across restarts.

The selection is saved with your other Step 2 settings, in HKCU\Software\Synapic\Engine, under TagKeywords, TagCategories and TagDescription (each a DWORD, 1 or 0). A partial selection survives closing the app, so a choice made once for one batch is the default for every batch after it. See What Step 2 remembers and, for reading or resetting the values directly, Files, folders and registry keys.

Choosing a selection on purpose

SelectionWhen it makes sense
All threeThe normal case: a complete record for each image.
Keywords onlyYou curate categories and descriptions by hand and want Synapic to do the tedious part. Watch for the warning line and expect Step 4 summaries to count the same items as successful, which they are.
Keywords and descriptionYour catalog's Categories field is a controlled vocabulary that the model should not write into.
Description onlyRare: you want prose for an accessibility or catalogue-text workflow and nothing else.

A partial selection is a durable decision.

Because it is saved and re-applied silently, a selection set for a one-off run is easy to forget. If a batch surprises you with missing fields, this page is the first place to look — before the model, the prompt, or the inference server, none of which are responsible.
