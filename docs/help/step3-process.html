Step 3 — Process

Nothing to decide here: press Start and watch, or leave it running. This is the step that writes to your library, so the controls around stopping it are worth knowing.

The controls

ControlWhat it does
Start ProcessingBegins the batch: fetch the items, then tag and write them one by one. Disabled while a batch is running, and while Step 2 has no tag field ticked.
PauseStops taking new images. Items already in flight finish and are written, so pausing never abandons half-tagged work.
ResumeContinues from where the batch stopped.
AbortCancels the batch. It always wins over a pause, and it takes effect as soon as the items in flight have been dealt with.

Pause is finished-work-safe; abort is not a rollback.

Aborting stops the run, but every image already tagged and written stays written. There is no undo step: use a small folder or a scratch collection if you want to experiment freely.

Reading the progress line

What you seeMeaning
Fetching items…The run is still collecting the work list, before any tagging. For Daminion this is paging through the catalog, which can take seconds or minutes on a large scope. Nothing has been tagged yet.
12/40 (0 failed)Items completed out of the total, with the failure count. The total is known once fetching finishes.
ETA ~3m 20s remaining — ~10s per imageTime remaining and the average cost of one image, both estimated from completed items. It appears once the first image has finished.
No items matched the current filtersThe batch found nothing to do. Check the scope, filters and limit in Step 1 — the model was never asked.
The current file nameThe image being worked on right now.

Expect the first image to take much longer than the rest.

Until the model is loaded, the app is waiting rather than tagging. On a cold start that can be a minute or more, and the model download (about 860 MB) happens here too if it has never run on this machine. Judge the per-image time from the second image onwards.

What one image involves

  1. The image is obtained: read from the folder, or downloaded from Daminion — full size, scaled, or as a 200-pixel thumbnail, depending on your Step 1 settings.
  2. It is sent to the inference server, which returns a category, keywords and a description in one call.
  3. The fields you ticked in Step 2 are written to the file or the catalog.
  4. The outcome is recorded for Step 4, and a line is appended to the log.

Up to four images are in flight at once, which is why the per-image time on screen (about ten seconds on a CPU) is longer than the rate the batch actually finishes at. See The five-step workflow.

While a batch runs

  • The wizard is locked: you cannot change steps or settings mid-run. Pause or abort first.
  • Every completion is written to logs\synapic.log as it happens, so closing the window by accident does not lose the record of what was written.
  • The log pane keeps the most recent lines on screen; the file keeps the whole run.
  • Step 4 is filled in as the batch goes, so you can switch to it once the run finishes (or after aborting) and see everything that happened.

Do not stop the inference server from the toolbar mid-batch.

Everything queued fails immediately. If you need the memory back, pause the batch first, wait for the items in flight to finish, then disconnect or stop.
