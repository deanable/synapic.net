Welcome to Synapic Help

Synapic tags an image library with a vision-language model that runs on your own machine, and writes the result into the images themselves or into a Daminion catalog. Nothing is uploaded anywhere, and there are no API keys to configure.

What Synapic does

For each image, one model call produces three things: a category, a set of keywords, and a description. Synapic writes the ones you ask for, and you choose where they land:

  • into the image file's own metadata (XMP), for a folder on disk; or
  • into your Daminion catalog, through the Daminion API.

The window has four views down the left side. Settings holds every configuration the app has — the source and its server, the inference server, the engine, the operation rules and the app preferences — and the other three, Tagging, Deduplication and Upscaling, run over the source it names. The engine itself is a second program, the inference server (also called the sidecar); Synapic starts it for you once one is built.

Two things worth knowing up front

Still only keywords? Check the tag fields before anything else.

The model always returns all three fields. The app writes only the ones ticked under Tag fields in Settings › Inference engine, and it does that quietly — the log still says the item was updated. If your catalog turns up with keywords but no category or description, that checkbox row is the cause; see Tag fields: what gets written.

The first batch is always the slow one.

The first run downloads the model (about 860 MB) and loads it into memory before the first image is tagged. Later runs reuse the downloaded model and start tagging in seconds. Timings that look alarming on the first batch are usually this, not a fault.

What is new in this version

  • Configuration has one home. The source, the server, the engine, the operation rules and the app preferences now sit in one scrolling column on the Settings view, with a search box over it. The other three views hold no configuration at all, so nothing is set up twice. See The Synapic window.
  • The sidebar replaced the dashboard and the step chain. There is no start screen and no numbered wizard: the four rows are the navigation, and picking one opens that view. See How a run works.
  • One layout for every operation. Each processing view shows a read-only Working on summary of the shared source and then its Output: the run bar, the operation's own controls, its log and, for tagging, its report.
  • System-prompt history. Every system prompt you commit in the engine settings is remembered, so earlier wording is one click away instead of gone. See Prompts.
  • The engine says what a run will write. A partial Tag fields selection now warns on screen, so a run that was only ever going to write keywords says so before it starts. See Tag fields.
  • A narrow window keeps its content. Below roughly 1000 pixels of width the sidebar collapses to an icon-only rail.

Using this help

The help window has three tabs: Contents to browse topics by task, Index to look up a word such as a setting name, and Search to search the full text. Every topic ends with links to related topics.

Press F1 in the app to open the topic for whatever you are looking at — the section or the exact setting under the focus, the sidecar topic while no server exists, otherwise the view on screen.
