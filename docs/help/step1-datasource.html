The data source

A run answers one question first: which images? That is decided on the Settings view, above everything else, because nothing else about a run means anything until it is answered. The same section also sets how much of it to process.

Two kinds of source

SourceWhen to use itWhere the tags go
Local FolderImages on this machine or a mounted share. The simplest and fastest path, and the safest way to trial the model.Into the image files themselves, as XMP metadata
Daminion ServerImages managed by Daminion, where the catalog is the source of truth.Into the Daminion catalog, through its API

Choose one in Settings › Data source, with the radio buttons under the two lights. The panels below them are mutually exclusive, and the rest of the panel only shows what applies.

The two source lights

Above the radio buttons, two lights are always on screen — the quickest answer to "what am I working with?" before you commit to anything:

LightGreen meansRed means
DaminionA session is live; the line beside it names the server URL.Nobody is signed in. Credentials typed into the form do not count until the server accepts them.
FolderThe chosen folder exists; the line beside it names the folder, and says so when subfolders are included.No folder is selected, or the typed path does not exist (a typo, or a drive that is not mounted).

Check the lights before a run: they are the cheapest answer to "is there anything here to work on?". A red light means the next batch would fetch nothing, so fix the source before starting it.

Local folder

  1. Choose Local Folder.
  2. Type a path into Folder containing images, or use Browse… to pick one.
  3. Tick Include subfolders (recursive scan) if you want the whole tree rather than just that folder.

Synapic collects files with the extensions it can read and write: .jpg, .jpeg, .png, .tif and .tiff. Anything else in the folder is ignored, which is why a scan of a mixed folder can find fewer images than the folder appears to hold.

A folder is not just for testing.

Because the tags go into the files, a tagged folder is portable: copy it to a machine without Synapic and the keywords and description travel with the images. That makes a folder run the right choice for an archive you own outright, and for any library that is not in Daminion yet.

The processing limits

This section also owns the two limits that decide the size of a batch: how many items to take, and how much of each image the model sees. The processing views do not ask for the source a second time: they report it read-only — the same two lights and the record count — so a run is never started blind about what it will touch. See How many items, and how much of each image.

What this section is not

  • It does not start anything. Choosing a source only fills in the session; processing begins in the operation's own view.
  • It does not validate that your folder contains images before you leave. Synapic tells you when the batch starts, in the log — "Found 0 image files" is the line to look for when a run finishes suspiciously fast.
  • It does not change your files. Nothing is written until a batch runs.

Your source comes back next time.

On Windows, a successful Daminion connect saves the connection, scope and filters, and Synapic reconnects to that server automatically on the next launch — so the record count is there before you touch anything. A failed login never overwrites a working set; the stored password is protected with Windows DPAPI. The local folder path is kept in the app config, so the folder you used last is still selected when you come back.
