Setup guide

Everything, in order: install, get an inference server, point Synapic at your images, tune the engine, run a batch and check the result. Each stage ends with a checkpoint, so you know it worked before moving on. The first pass takes about an hour; almost none of it is repeated later.

Press F1 anywhere in the app to open the help at what you are looking at. This guide is the map; the F1 topics are the detail.

Before you start

Synapic runs on Windows, macOS and Linux. It needs the .NET 10 desktop runtime (the Windows installer takes care of it) and about 4 GB of disk for the app, the model and the built server. An NVIDIA GPU makes tagging much faster but is not required: the CPU build runs anywhere. Full numbers in What you need.

Have a small test folder ready.

Twelve or so images you can look at in your own viewer. Every stage below can be rehearsed on that folder before a Daminion catalog or a holiday's worth of photos is at stake.

Stage 1 — Install Synapic

  1. Run Synapic-Setup-win-x64.exe and accept the administrator prompt (the app installs under C:\Program Files\Synapic).
  2. Let the installer handle the .NET runtime if Windows complains about it — it installs silently and may ask for a restart.
  3. Finish the wizard; launching Synapic from it is fine.

Unattended installs, other platforms and upgrades: Installing and upgrading.

Stage 2 — Get an inference server

The model runs in a separate program (the sidecar). Nothing can be tagged until one exists, so the workspace stays disabled and a banner says Inference sidecar required until you fix that:

  1. In Settings › Inference server, press Download on the CPU row of Platform variants to fetch the prebuilt executable — works on any machine, no toolchain needed. CUDA users: the CUDA row, if this machine has an NVIDIA GPU.
  2. No prebuilt fits? Build sidecar compiles from source; that first build downloads a private Python and the packages the model needs, so expect minutes.
  3. Wait for the status dot at the bottom of the sidebar to turn green: Server running (port …). The very first launch is slow — up to a couple of minutes — because the executable is unpacked and the model is loaded.

Checkpoint: the workspace is no longer disabled.

The Settings sections respond and the log shows the server's port. If the dot stays red, read Build the inference server and Troubleshooting: the inference server before going further.

Stage 3 — Choose your images

  1. In Settings › Data source, choose Local Folder.
  2. Browse to your test folder. Leave Include subfolders off for the rehearsal.
  3. Watch the folder light turn green (it names the folder it will use) and the record count appear beside it.
  4. Daminion users: choose Daminion Server instead and carry on with Stage 4.

Synapic tags JPEG, PNG and TIFF files; RAW files are skipped. Details and edge cases: The data source.

Stage 4 — Connect and scope Daminion

  1. Enter the server URL, your username and password, then Connect. The password is stored encrypted for your Windows user only; it is never written to plain text. See Connecting to Daminion.
  2. Check the Active catalog line: the catalog follows the server URL, so a wrong URL lands in a different catalog.
  3. Pick a Scope — entire catalog, keyword search, shared collection or saved search — then the filters (status, "only items with untagged…"). Details: Scope and filters.
  4. Read the record count beside the lights: it runs by itself on launch and after every scope or filter change, so you can see what the scope selects before anything runs. Set the Max items ceiling for the first run in the same section, under How many items, and how much of each image (100 is the default).

Batch size and image scaling: How many items, and how much of each image.

Stage 5 — Configure the engine

  1. Model. The default LiquidAI/LFM2.5-VL-450M is the right first choice. Use Download model… if the list shows it as not downloaded yet.
  2. Device. CPU everywhere; CUDA on an NVIDIA GPU; MPS on Apple silicon. See Inference engine.
  3. Tag fields. Tick which of the three results get written. All three on is the default — and the single most common cause of "only keywords came out" is one of these boxes unticked. See Tag fields: what gets written.
  4. Prompts (optional). Leave both boxes blank for the first run: the built-in instruction already asks for category, keywords and description. Wording later: Prompts.
  5. Scoring controls. Leave the defaults (0.3 / Both / 0.5). They do not change what the local model produces. See Scoring settings.

The engine settings are remembered.

They are saved with the rest of the configuration and restored next launch — a setting changed once keeps applying. What is remembered and how to reset it: What the engine settings remember.

Stage 6 — Run the batch

  1. Pick Tagging in the sidebar and press Start Processing. Progress, ETA, pause and abort are explained in Running a tagging batch.
  2. Watch the log in the same view: one line per image reports the category, keyword count and the start of the description.
  3. The first image also triggers the model download (about 860 MB) if this machine has never used it. Timings that look alarming on the first batch are usually that, not a fault.

Checkpoint: rows appear in the report with status Ok.

If rows say failed, or the log shows errors, stop and read Troubleshooting — running a large batch against a broken setup only multiplies the cleanup.

Stage 7 — Review and verify

  1. Read the report below the run: the summary line and the per-file rows. See Tagging results.
  2. Open one of the files in your own image viewer or in Daminion and confirm the keywords, category and description are actually there. What lands where: What gets written to your images.
  3. Daminion users: Verify Daminion Writes re-reads the catalog and confirms the writes without the manual spot check.
  4. Export CSV keeps a record of the run if you need to argue with it later.

Stage 8 — Optional: deduplication

The Deduplication view finds near-identical images by perceptual hash — over the shared source, a local folder or the Daminion scope you chose — groups them, and lets you tick which copies to keep (or let the oldest/newest/smallest/largest keep-set rule do it) before you tag, move or delete the rest, or remove them from the catalog. It is a separate operation with the same source and its own rules; it never touches the tagging batch.

Stage 9 — Make the app yours

Two layers of settings, both optional:

  • In the app. What you set in the data source and the engine comes back next launch — connection, scope, filters, limits and all of the engine settings — from the Windows registry (defaults each run on macOS and Linux). The local-folder box is the exception: reselect it each launch. Every field, default and storage location is listed in Settings reference.
  • In the app preferences. Appearance, the logging level, whether the diagnostics drawer is shown, and what a new session starts from. All of them are the last section of the Settings view.
  • In the config file. %APPDATA%\Synapic\config.json holds the keys that have no control in the app: ui.telemetryEnabled (local counters, off by default) and ui.theme. Explained in Application settings.

Backups, registry paths and the rest: Files, folders and registry keys.
