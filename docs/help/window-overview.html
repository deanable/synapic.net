The Synapic window

Everything happens in one window, and the window has two parts: a sidebar down the left that is the only navigation, and one view at a time to its right. There is no dashboard, no numbered step chain and no toolbar: the row you pick in the sidebar is the view you get.

The four views

The sidebar lists four rows, in this order. The lit row is the view that is open; the app derives it from what is on screen rather than remembering it, so the two can never disagree.

RowWhat it is for
SettingsEvery configuration the app has, in one scrolling column: the data source and its server, the inference server, the inference engine, the deduplication and upscaling rules, and the app preferences. It is the app's home — it is what you see on launch.
TaggingRun the model over the shared source and write the tags. Opens that operation's processing view.
DeduplicationScan the shared source for near-duplicate images and resolve the groups.
UpscalingEnhance the resolution of the shared source's images, with AI (Swin2SR) or Lanczos.

The configuration is not repeated in the processing views.

Each processing view carries a read-only summary of what it is about to run and nothing else: no folder picker, no model list, no threshold. That is deliberate, so a setting has exactly one home and cannot be changed in two places. Where each one lives: How a run works.

The bottom of the sidebar

The server's state and the help entry are pinned to the bottom of the sidebar, so both are on screen from every view. There is no Start/Stop/Build control here: the buttons live in the Settings view's Inference server section, one home each.

What you seeMeaning
Status dot and textThe state of the inference server. The wording is the table below.
The device lineThe compute device the running server reports for the loaded model. It appears only while a server is up.
A progress barShown while a model or a server variant is downloading, with the size and speed written beside it.
A warning lineShown when the server reports a device other than the one selected — a silent CPU fallback, spelled out.
HelpOpens this help at its home page. F1 opens the topic for what you are looking at instead.

What the status text means

StatusMeaning
Detecting server…Startup: Synapic is looking for a server executable next to the app or in a development checkout.
Server not detectedNo server executable was found. Build or download one; a banner across the top of the workspace says so and the rest of the app stays disabled.
Building server…A build is running. The first build downloads Python and the inference packages, so it is the longest step in the whole product.
Server stoppedA server exists but is not running. Press Start Server in the Settings view.
Server starting… (first launch can take up to 2 minutes)The process is up and Synapic is waiting for its /health report. A cold start unpacks and loads the model.
Server running (port NNNNN)Ready to tag. The port is chosen by the operating system and is for this run only.
Server error — see logThe server exited or never became healthy. The log has its own output; see Troubleshooting: the inference server.

"stale build, rebuild recommended"

Appended to Server running when the server executable is older than the inference source code it was built from. It still works; you are being told that a rebuild would pick up changes. Prebuilt releases never show this — it is a developer-checkout message.

The Settings view

One scrolling column, in the order a run meets it. A search box at the top filters the column to the sections that mention what you type; an empty query shows every section.

SectionWhat it configures
Data sourceWhat to work on: a local folder or a Daminion login, the catalog scope and filters, the record count that keeps itself current, and the processing limits (how many items, and how much of each image).
Inference serverThe local sidecar: its status, Start / Stop / Build Server, whether it starts with the app, and one row per platform variant with Build sidecar or Download.
Inference engineThe model, the device, which tag fields get written, the scoring controls and the prompts — everything a tagging run uses.
DeduplicationThe scan rules (algorithm, threshold, server-hash comparison) and the keep-set rule.
UpscalingWorkflow, factor, precision, output format and the post-processing the upscaling run uses.
App preferencesAppearance, logging, what a new session starts from, and this build's version, links and settings-file path.

Every section is on screen at once — the column scrolls rather than hiding sections behind tabs, so nothing is one tab away from being forgotten.

A processing view

Tagging, Deduplication and Upscaling share one layout, so learning one is learning all three:

RegionWhat it shows
Working onA read-only summary of the shared source — the same two source lights and the record count the Settings view shows — so a run is never started blind about what it will touch.
OutputThe run bar (progress, ETA, the file being worked on, and the primary action), the operation's own controls, its log, and — for tagging — its report.

Navigation is locked while a batch runs.

The four sidebar rows are disabled while a run is in flight, so you cannot navigate away from a batch mid-flight. Finish, stop or abort it first; see Running a tagging batch.

A narrow window

Below roughly 1000 pixels of window width the sidebar collapses to a narrow icon-only rail: each row keeps its glyph and drops its label, the app title and the wide status lines go with it, and the Help entry shortens to ?. A narrow window therefore keeps its content width instead of losing it to the navigation. Widen the window and the labels come back.

The diagnostics log

Off by default. When Show diagnostics is ticked in Settings › App preferences › Logging, a log drawer appears along the bottom of the window: the app's own progress messages, anything the inference server writes to its error stream (prefixed [sidecar:err]), and any warnings the app raises.

The same content is written to logs\synapic.log, with the previous run archived. Each processing view has its own run log inside it, so a batch's lines are readable without turning the drawer on. Reading the log explains the lines worth knowing.

Keyboard

  • F1 opens this help at the topic for what you are looking at: the section or the exact setting under focus first (settings land on their row in Settings reference), then the sidecar topic while no server exists, otherwise the view on screen. The sidebar's Help button opens the home page instead.
  • Alt+Home returns to the Settings view from anywhere, the same as clicking its sidebar row.
  • Ctrl+S saves the current configuration to disk without waiting to leave the view.
  • Delete removes the highlighted entry from the saved system-prompt list in the engine settings. See Prompts.
  • In the log and the results grid, the usual navigation keys work (Tab, arrow keys, Ctrl+C to copy the selected text).
