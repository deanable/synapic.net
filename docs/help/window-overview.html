The main window

Everything happens in one window: a thin toolbar for the inference server at the top, the wizard in the middle, and a live log along the bottom.

The toolbar

ControlWhat it does
Start ServerStarts the inference server. Synapic already starts it for you when the app opens; this is for when you have stopped it deliberately.
Stop ServerShuts the inference server down, freeing its memory. Tagging is unavailable while it is stopped.
Build ServerAppears only when no server executable exists at all, and opens the same build options as the setup panel below.
HelpOpens this help at its contents. F1 opens the topic for what you are looking at instead: the setup panel while no server exists, otherwise the step on screen.
Status dot and textThe state of the inference server at a glance; the wording is listed below.
Progress barAppears while a model is being downloaded, with the size and speed written next to it.

What the status text means

StatusMeaning
Detecting server…Startup: Synapic is looking for a server executable next to the app or in a development checkout.
Server not detectedNo server executable was found. Build one; the setup panel appears automatically.
Building server…A build is running. The first build downloads Python and the inference packages, so it is the longest step in the whole product.
Server stoppedA server exists but is not running. Press Start Server.
Server starting… (first launch can take up to 2 minutes)The process is up and Synapic is waiting for its /health report. A cold start unpacks and loads the model.
Server running (port NNNNN)Ready to tag. The port is chosen by the operating system and is for this run only.
Server error — see logThe server exited or never became healthy. The log has its own output; see Troubleshooting: the inference server.

"stale build, rebuild recommended"

Appended to Server running when the server executable is older than the inference source code it was built from. It still works; you are being told that a rebuild would pick up changes. Prebuilt releases never show this — it is a developer-checkout message.

The setup panel

When Synapic cannot find a usable server, or when a variant is still missing, a panel appears under the toolbar listing each variant with its state and a way to get it: Build sidecar when this checkout can build, and Download to fetch the prebuilt executable from the latest release.

A variant that already reads Built offers Update instead: it replaces that executable with a fresh one — building from source when this copy can, re-downloading the latest release when it cannot — and restarts a running server on the new build.

  • The wizard below stays disabled until at least one server exists. This is deliberate: nothing in the wizard can work without one.
  • While a variant is building, its row shows a progress bar and the stage it is in (fetching Python, installing packages, packaging).
  • Each row's detail line says what that variant is for — usually that it runs anywhere, or that it needs an NVIDIA GPU.

See Build the inference server.

The wizard

Five tabs select the step:

TabWhat you decide there
1 · DatasourceWhich images: a folder, or a Daminion catalog with scope and filters.
2 · EngineModel, device, prompts, and which of the three tag fields get written.
3 · ProcessRun the batch, watch progress, pause, resume or abort.
4 · ResultsWhat happened per image: export, retry, verify.
DeduplicationA separate tool that finds near-duplicate images in a folder.

Below the tabs is one navigation row: a hint describing what the next step needs, a Back button, and a main button whose label changes with the step (Next, Start Processing, and so on). Two things can block movement:

  • A red validation message, for example when Step 1 has no datasource or Step 2 has no tag field ticked. The message names what is missing.
  • An Start Over button appears once a run has produced results; it clears the session and returns you to Step 1.

Navigation is locked while a batch runs.

While Step 3 is processing, you cannot switch steps. Pause or abort the batch first — changing the engine half-way through a run is not something the app tries to make sense of.

The log

A live view of what the app is doing, newest line at the bottom, scrolling itself as the batch progresses. It carries three kinds of line: the app's own progress messages, anything the inference server writes to its error stream (prefixed [sidecar:err]), and any warnings the app raises.

The same content is written to logs\synapic.log next to the executable, with the previous run archived. Recent lines are kept in the pane, so a long batch does not grow the window without limit.

Reading the log explains the lines worth knowing.

Keyboard

  • F1 opens this help at the topic for what you are looking at: the setup panel while no server exists, otherwise the step on screen. The toolbar's Help button opens the contents instead.
  • That is the only global shortcut: the rest of the controls are the toolbar and the wizard buttons, and there is no Ctrl+P.
  • One key matters: Delete removes the highlighted entry from the saved system-prompt list in Step 2. See Prompts.
  • In the log and the results grid, the usual navigation keys work (Tab, arrow keys, Ctrl+C to copy the selected text).
