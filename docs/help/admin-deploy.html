Deploying to many machines

Four things have to be right on a target machine: the app, the inference server next to it, the .NET runtime, and the model — which is the only piece that normally needs the internet.

What a working machine has

PieceWhere it livesHow it gets there
The applicationC:\Program Files\SynapicThe Windows installer, silently if you like: silent installation.
The inference serversynapic-inference.exe in the same folderShips inside the installer, and can be replaced on its own — see below.
The .NET 10 Desktop RuntimeMachine-wide, standard Microsoft locationThe installer supplies it (bundled or downloaded). Detect it in advance to avoid surprises in the field.
The model%LOCALAPPDATA%\Synapic\models — per userDownloaded on first tag, or copied in for offline machines.
A route to DaminionYour own networkNothing to install; just reachable, with credentials that may write.

Updating the inference server on its own

The standalone inference server is published as a release asset for each platform, so a site can move to a new server — or to CUDA — without reinstalling the app:

AssetGoes to
synapic-inference-win-x64.exeRename to synapic-inference.exe in the install folder.
synapic-inference-win-x64-cuda.exe.part1 and .part2Reassemble with the bundled reassemble-...bat helper, check the SHA-256 it prints, then rename and copy as above. The CUDA bundle is about 2.5 GB, which is why it ships in parts: GitHub rejects single release assets that large.
synapic-inference-osx-arm64, synapic-inference-linux-x64Same idea on those platforms, named synapic-inference.

SHA256SUMS.txt covers every published asset, so an installer script can verify what it downloaded.

Offline machines

  1. Install the app from a setup that has the .NET runtime bundled, so nothing is downloaded at the Ready step.
  2. Copy the inference server in, if the installer did not already carry the variant you want.
  3. Copy the model cache into each user's profile: %LOCALAPPDATA%\Synapic\models. The model is per user, because that folder is per profile — on a shared machine, seed it at first logon rather than once machine-wide.
  4. Confirm the app starts with the status reading Server running, and run five images.

The model cache is deleted on uninstall.

An uninstall/reinstall cycle on a machine with no internet leaves the app unable to tag until the cache is copied back. Keep a copy of the folder with your deployment media. See Upgrading and uninstalling.

A diagnostic switch worth knowing.

The inference server respects SYNAPIC_DISABLE_AUTO_DOWNLOAD=1, which stops it from fetching model weights. That is how the build pipeline smoke tests a freshly built server without downloading 860 MB; with no weights present, tagging naturally fails. It is not a supported way to lock down a normal install.

Settings on a managed fleet

SettingCan you pre-seed it?
Step 1 and Step 2 settings (registry, HKCU\Software\Synapic)Yes, per user, with a login script writing the values listed in Files, folders and registry keys.
The Daminion passwordNo. It is encrypted with the user's own Windows credentials (DPAPI), so a value copied from another machine or account cannot be decrypted. Each user enters it once.
Auto-launch of the inference serverYes — ui.autoLaunchSidecar in %APPDATA%\Synapic\config.json. It ships true.
Usage countersYes — ui.telemetryEnabled, false unless a user opts in. They are local counters in the log folder, not telemetry to a service.

Security and endpoint protection

  • No inbound ports. The inference server listens on a loopback address and an operating-system-assigned port, and publishes that port in a small file in %TEMP% so the app can find it. No firewall rule is needed for other machines to use Synapic.
  • Endpoint security may still object. A bundled Python executable that spawns a local listener, and a temporary file containing a port number, are exactly the kind of behaviour heuristic tools flag. If a machine shows the server failing to start where others succeed, check the security product's log before suspecting the app.
  • No images leave the machine. The only outbound traffic is to your Daminion server, plus Microsoft for the runtime and the model host for weights on first use.
  • The password is protected, not shared. DPAPI means the stored Daminion password is readable only by that user on that machine. Plan for a per-user login, not a deployed secret.

Planning capacity

MachineReasonable expectation
Standard desktop, CPUAround ten seconds per image, four at a time. A thousand-image backlog is an hour or two of unattended work.
Workstation with an NVIDIA GPU and the CUDA serverSeveral times faster, but not proportionally to the hardware — four parallel calls share one model. Benchmark on your own images.
Shared machine, several usersEach user's app starts its own inference server, so memory use multiplies. Prefer one tagging machine over several users tagging at once on a modest box.
