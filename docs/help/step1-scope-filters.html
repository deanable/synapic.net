Scope and filters

Scope says which part of the catalog to look at; filters say which of those items are worth your time. Together they decide the batch, so a count before you start saves hours.

Scope

ScopeWhat it selectsYou also provide
Entire catalogEverything the login can seeNothing
Keyword searchItems matching search termsA Search term
Shared collectionItems in one shared collectionA collection, picked by name or by id
Saved searchItems matching a saved search defined in DaminionA saved search, picked by name or by id

For collections and saved searches, the list is read from the server when you connect. The small id box beside each picker is for the cases where the list is empty or you know the id: type it and the picker follows. That is also how a saved search or collection is restored from a previous run.

Saved searches are the best-kept secret in Step 1.

Daminion's own query language is far richer than "keyword search" here. Build the selection you want in Daminion, save it, then run Synapic against that saved search — and rebuild the batch after your curation changes, without touching Synapic.

Filters

FilterWhat it does
StatusRestricts to items with a Daminion status flag: All, Approved, Rejected or Unassigned. Use it to keep a run inside a reviewed set, or to tag only what nobody has triaged yet.
Only items with untaggedThree independent checkboxes — Keywords, Categories, Description. Each one limits the batch to items where that field is still empty. Tick one to fill a gap, or all three to find items nobody has touched.
Select all untaggedTicks all three of the above in one press. The usual starting point for a first pass over a catalog.

Counting before you start

Count matching items asks the server how many items the current scope and filters select, without downloading anything. It is the cheapest sanity check Synapic offers, and it is worth doing every time before a long batch:

  • A count of 0 means the batch will do nothing. Check the scope and the status filter before assuming the model failed.
  • A count in the hundreds of thousands means you probably wanted a filter.
  • If the count looks implausible, the log records it. Synapic falls back to a sanity value if the server reports a count larger than the catalog itself.

The filters are applied by Daminion, not by Synapic.

Untagged-field and status filters become part of the request, so the batch never downloads items it would only skip. That also means an item whose metadata lives outside the fields Daminion considers "tags" can look untagged to Synapic while looking complete to you.

Deciding what to process first

  1. Start with Saved search or Shared collection and a small limit — a hundred items at most — to see the model's output on your own material.
  2. Review the results in Step 4, and look at a few items in Daminion.
  3. Only then widen the scope, or lift the limit, for the full batch.

On a CPU-only machine a catalog of 10,000 images is an overnight job, so it is worth being sure about the settings before you start it.
