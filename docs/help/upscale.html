Upscaling (Feature enhancement)

A resolution-boosting tool in the spirit of Daminion's Feature enhancement utility: pick a source, choose how aggressive the enhancement should be, and Synapic rewrites every image at a larger size — with AI super-resolution (Swin2SR) or with plain high-quality interpolation. The algorithm runs in the inference server, exactly like tagging does.

It has its own route.

The start screen offers Upscaling beside Tagging and Deduplication, and that route is Datasource → Upscaling only: the Engine, Process and Results steps never appear. From the tagging route the same tool stays reachable through the Upscaling tab once you reach Results. See Source first, then the route.

Choosing the source

The source is the one configured on the start screen — a local folder or the Daminion catalog scope (entire catalog, keyword search, shared collection or saved search). Step 1 shows the same two source lights read-only, and the source is changed on the start screen (⌂ Home), where the record count sits next to it.

  • Catalog source. Each item is checked out, its original downloaded, enhanced, and checked back in as a new file version with a comment recording the parameters used. If the upload fails, the checkout is undone so no item is left locked.
  • Local source. The enhanced image is written beside the original as name_upscaled.ext; the original file itself is never modified.

Settings

SettingWhat it does
Workflowquality: the classical Swin2SR model (2x or 4x) — the faithful, detail-preserving choice. balanced: the real-world model with a denoise blend, better on noisy or compressed sources. fast: plain Lanczos interpolation, no model, no download — instant and predictable.
Factor2x doubles each edge; 4x quadruples it (and the pixel count with it).
Precisionauto, fp16 or fp32 for the AI workflows on a CUDA build. Disabled for fast.
Outputkeep writes the source's own format; JPEG, PNG and WEBP convert. JPEG and WEBP quality is the Quality field (70–100).
DenoiseBalanced workflow only: how much of the AI result to keep, blended toward plain interpolation at the low end. At 1.0 the output is pure AI; lower it when the model sharpens noise.
SharpenUnsharp mask applied after upscaling, 0–2 (0 = off).
Overwrite existing outputOff, a second run that would hit the same output file writes name_upscaled_1.ext instead of replacing it.

Start with fast, then decide.

The fast workflow needs no model download and finishes instantly, so it is the quickest way to check that a source and a factor are what you wanted. Switch to quality or balanced when the result has to hold up to inspection.

Running the batch

  1. Press Run Upscale Batch. The parameters are echoed into the log, then each item is fetched, enhanced and written in turn.
  2. Watch the progress bar, the counter and the ETA. The first quality/balanced item also downloads the Swin2SR weights from Hugging Face (tens of megabytes, once per machine), so the first run starts slower than the rest.
  3. Press Stop to end the run: items already finished stay finished, the item in flight is cancelled, and no new item starts.

One inference runs at a time — the same one-worker behavior the original application had — so a catalog of 300 images is a steady sequence rather than a burst, and the ETA reflects reality after the first couple of items.

A catalog run writes to the server.

For a Daminion source, every successful item becomes a new checked-in file version. The previous version remains in the catalog's version history, but the item's file is replaced — run a small scope first if you have not used the tool before.

What the log tells you

Every stage writes to logs\synapic.log beside the executable:

  • One line at the start names the source and every parameter of the run (workflow, factor, precision, output, quality, denoise, sharpen, overwrite).
  • One line per item with the dimensions before and after, the workflow and model used, and how long inference took.
  • One line per failure: a checkout the server refused, an original that would not download, an upscale that errored, or a check-in the server rejected — each item is reported on its own and the batch continues.
  • One line when the batch finishes with processed, succeeded and failed counts.

What this tool is not

  • It does not retouch, denoise by hand or change composition — it makes the same image bigger.
  • It does not touch the original in a local source, and it does not run unattended: the batch stops when you close the step or press Stop.
  • It needs the inference server. Fast works as soon as the server is running; quality and balanced additionally fetch their model on first use.
