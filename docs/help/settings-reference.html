Settings reference

Every setting Synapic has: what it does, its default, and where it is stored. Each row is anchored, so F1 over a control in the app opens this page at that row — or follow the links from the step topics.

Where settings live

LayerWhat it holdsWhen it is written
The step formsThe live values a run uses, held in memory for the session.Continuously as you type; pushed to the session when you leave the step.
HKCU\Software\Synapic (Windows only)What the forms restore from next launch: \Engine for Step 2, \Daminion for Step 1. Per user, no admin rights.When you leave the step; the Daminion key only after a successful login. On macOS and Linux these stores do not exist — the forms start from defaults every run.

Do not hand-edit while Synapic is running.

The app reads settings at startup and writes them when you leave a step, so a hand edit made mid-session can be overwritten. Close the app first, and see Files, folders and registry keys for the full path list.

Step 1 — Datasource

The source choice and the local-folder fields are session state: they are snapshotted into datasource.* in config.json but restored from nowhere, so each launch starts on Local Folder with an empty path.

SettingWhat it doesDefault
Local Folder / Daminion Server
datasource.type		Which source the wizard reads: files in a folder on disk, or a Daminion catalog over its API. Only one can be active at a time.Local Folder
Folder containing images
datasource.localPath		The folder to scan. With Include subfolders off, only the images directly in it are tagged. JPEG, PNG and TIFF are read; RAW files are skipped.empty (choose each launch)
Include subfolders
datasource.localRecursive		Descend into subfolders when scanning. Off keeps a first test honest: you know exactly which files were candidates.off

Step 1 — Daminion connection

These live in HKCU\Software\Synapic\Daminion and mirror into datasource.daminion.* in config.json, except the password. The registry copy is written only after a successful connect, so a mistyped password never replaces a working configuration.

SettingWhat it doesDefault
Server URL
serverUrl · ServerUrl		The Daminion server's web address, for example http://dam.local/daminion. The URL also decides which catalog the login lands in.empty
Username
username · Username		The account used for the API session.empty
Password
registry: PasswordEncrypted		Protected with Windows DPAPI for your user on this machine, then base64-encoded. It is never written to config.json, and copying the registry value to another machine or user does not work — by design.empty

Step 1 — Scope and filters

What the batch considers: all of it lives in the Daminion registry key and datasource.daminion.*. The narrative version is Scope and filters.

SettingWhat it doesDefault
Scope
scope · DaminionScope		Entire catalog (all), Keyword search (search, with the term below), Shared collection (collection) or Saved search (saved_search). A saved search is also how you control processing order — the API returns items in the server's order, not yours.Entire catalog
Search term
searchTerm		The keyword query, used only in the Keyword search scope.empty
Saved search id
savedSearchId		Selects a saved search from the dropdown (or an id typed by hand). Used only in the Saved search scope.empty
Collection id
collectionId		Selects a shared collection. Used only in the Shared collection scope.empty
Status
statusFilter		Restricts the batch to items with that approval status: all, approved, rejected or unassigned.All
Only items with untagged: Keywords / Categories / Description
untaggedKeywords · untaggedCategories · untaggedDescription		Three independent switches that keep already-tagged items out of the batch — the cheapest way to resume a big catalog where it left off. Select all untagged ticks them together.all off

Step 1 — Batch limits and image scale

Registry values MaxItems, ProcessAll, ResizeScale and UseThumbnailOverride, mirrored into processing.* (and datasource.daminion.maxItems) in config.json. Narrative: How many items to process.

SettingWhat it doesDefault
Max items
processing.maxItems · MaxItems		The ceiling for this run. The batch stops once it has taken that many items; 0 means no ceiling, same as Process all. Local-folder runs count files, Daminion runs count catalog items.100 (steps of 50)
Process all (page until empty)
registry: ProcessAll		Ignores the ceiling and keeps requesting pages of results until the server returns none — without it, a catalog larger than one API response looks fully processed when only the first page was. Stored in the registry only, not in config.json.off
AI image scale
processing.resizeScale · ResizeScale		Downscales the image before tagging: 100%, 75%, 50% or 25%. Smaller is faster and uses less memory; the model still sees the whole frame, with less detail. Quality falls off below 50%.100%
Use fixed 200px thumbnail (fast)
processing.useThumbnailOverride · UseThumbnailOverride		Asks Daminion for its 200-pixel thumbnail instead of the full image — dramatically faster on a big catalog, and it overrides the scale setting. Right for a triage pass, wrong for the run you intend to keep.off
Auto-paginate
processing.autoPaginate		Config-file only: keep fetching full pages (500 items) while the server keeps returning them. It is always on as written by the app; turn it off only to cap a runaway query at the first page.true

Step 2 — Engine

Step 2 restores from HKCU\Software\Synapic\Engine and mirrors into engine.* in config.json. Values are sent to the sidecar with every tag request. Narrative: Step 2 — Tagging Engine.

SettingWhat it doesDefault
Model id
engine.modelId · ModelId		The Hugging Face repository of the vision-language model to run. The list shows what is already in the local cache; Download model… fetches another. The id is sent with every request, so a run can use a different model than the previous one.LiquidAI/LFM2.5-VL-450M
Device
engine.device · Device		Where the model runs: CPU (cpu) works everywhere, CUDA (cuda) needs an NVIDIA GPU and is many times faster, MPS (mps) uses Apple silicon. The app picks whatever the built server supports.CPU
Task (shown read-only)
engine.task · Task		The model task format the sidecar loads with. Synapic's models are all image-text-to-text; it is displayed for diagnosis rather than edited.image-text-to-text
Tag fields: Keywords / Categories / Description
registry: TagKeywords · TagCategories · TagDescription		Which of the three model results get written. The model always returns all three; these three DWORDs decide what lands in the file or catalog. Registry only (not in config.json) — check them first when a field is missing. See Tag fields.all three on

Step 2 — Scoring controls

These do not change what the local model produces.

Confidence and probability settings belong to the scoring layer that interprets results (and to probability/zero-shot paths); the vision-language model's own output follows the prompts alone. Defaults are right for almost everyone — why they exist explains the mechanics.

SettingWhat it doesDefault
Confidence threshold
engine.confidenceThreshold · ConfidenceThreshold		Keywords scoring below this confidence are dropped from the result. Raise it for a tighter list, lower it to keep candidates worth reviewing.0.3
Probability mode
engine.probabilityMode · ProbabilityMode		Where scoring evidence comes from: LLM only (llm), Probability only (probability), or Both (both).Both
Prob. threshold
engine.probabilityThreshold · ProbabilityThreshold		The cut-off applied to probability-based scores, same idea as the confidence threshold on the other path.0.5
Candidate labels
engine.probabilityCandidates · ProbabilityCandidates		Comma-separated label list for probability/zero-shot scoring — the closed set of keywords the scorer chooses among. Empty means the model's own vocabulary.empty

Step 2 — Prompts

SettingWhat it doesDefault
System prompt
engine.systemPrompt · SystemPrompt		Optional context for the vision-language model ("these are botanical plates…"). It must not restate the output format — that belongs to the tag instruction. Every prompt you commit is remembered in %APPDATA%\Synapic\system-prompts.json, separate from this setting. See Prompts.empty
Tag instruction
engine.userPrompt · UserPrompt		The instruction sent for every image. Blank means the sidecar's built-in one, which asks for a JSON object with description, category and keywords; a custom instruction must keep asking for that shape or the reply is stored as a plain-text description. Blank is stored as blank, never as a frozen copy of the built-in wording.empty (built-in)
Embedding rescue
engine.embeddingRescueEnabled · EmbeddingRescueEnabled		Config and registry only, no UI. Persisted for compatibility with older setups; the local model does not use it. Safe to leave at 0.off

Application settings (config.json)

The ui.* block is read at startup from %APPDATA%\Synapic\config.json (off Windows: ~/.config/Synapic/config.json). These are the settings with no form in the UI — edit the file with the app closed. Saving preserves keys this version does not know about, so hand-added values survive.

SettingWhat it doesDefault
Auto-launch the inference server
ui.autoLaunchSidecar		Start the sidecar when the app starts (and stop it on exit). Set false to make Start Server a manual step — useful on machines where Synapic is opened only to browse results.true
Log level
ui.logLevel		Which levels the in-app log panel shows: verbose, debug, info, warning or error. The log file always records debug detail regardless — this only filters what you see on screen. See Logs, crashes and support.info
Usage counters
ui.telemetryEnabled		When true, app launches, batches, items, failures and dedup runs are counted into logs\synapic-usage.json so a support engineer can read them from a user-shared file. Strictly local: no network access, ever. When false, the counter is a no-op.false
Theme
ui.theme		Reserved. The value round-trips through config saves untouched, but the UI follows your operating system's light/dark setting today; changing this key has no visible effect yet.system
Config version
version		Schema version of the file (currently 2). Written by the app; do not hand-edit — an older app meeting a newer file still keeps unknown keys, but the version is how tooling tells them apart.2

The snapshot blocks are writable, too.

datasource.*, engine.* and processing.* in config.json are written from the wizard but not read back at startup (the forms restore from the registry instead). That makes the file a convenient place to stage a known-good working set for a colleague — and the reason a hand edit there looks like it "does nothing" on the same machine.

Deduplication (not persisted)

The dedup tool's settings live in the session only: every launch starts over. Narrative: Deduplication.

SettingWhat it doesDefault
Local Folder / Daminion CatalogWhich source the scan reads: files in a folder on disk, or the Daminion catalog scope chosen in Step 1 (entire catalog, keyword search, shared collection or saved search). Mirrors the datasource radios of Step 1 — the catalog side downloads each original to hash it, so it is slower than a local scan.Local Folder
Folder to scanThe folder whose images are compared, shown for the local source. Nothing outside it is read or touched.empty
AlgorithmHow similarity is computed: PHash (perceptual hash, the general choice), DHash, AHash (both gradient/average variants, cheaper) or ColorMoment (color statistics, slower, forgiving of crop-less edits).PHash
ThresholdHow similar is duplicate: from 0.5 to 1.0. Higher is stricter — near-exact copies cluster at 0.97+, resized and lightly edited images need lower.0.90
Auto-select keep-set: Oldest / Newest / Smallest / LargestFour switches that drive every group's per-item checkboxes at once. Each active switch ticks the item it names in every group (oldest/newest by capture date, smallest/largest by file size); several switches tick the union of their picks. A checked item is kept — the action applies to the unchecked ones. With no switch active, the first item of each group is kept. Toggling a switch recomputes the selection and overwrites manual tweaks.all off
Action for unchecked duplicatesWhat Apply does to every unchecked item across all groups: Tag the images as duplicates, Move the extras to a subfolder, or Delete them (local source — delete asks for confirmation first, because it cannot be undone). With the Daminion source the only action is Delete from catalog, which also asks for confirmation before removing the items from the catalog.Tag

Changing settings by hand

  • Close Synapic first: forms are saved when you leave a step, so an edit made while it runs can be overwritten.
