Connecting to Daminion

One login does the whole run: it lists the catalog, counts matching items, downloads the images, and writes the tags back.

Connecting

  1. In Step 1, choose Daminion Server.
  2. Fill in three fields:
    • Server URL — the Daminion server address, for example http://dam.local/daminion. Include the scheme.
    • Username and Password — an account that may read the items and update their metadata.
  3. Press Connect. It is enabled only once all three fields have something in them.
  4. Wait for the confirmation. A successful connect reports the server and how many saved searches and collections it found, and the panel starts to fill itself in.

Daminion permissions matter.

An account that can read but not write will let a batch run and fail at the write. Check the account's rights in Daminion if Step 4 reports failures that all look alike.

Which catalog am I in?

Daminion chooses the catalog from the server URL you logged in to, and has no API for listing a server's catalogs. So Synapic reports the one it landed on rather than offering a picklist:

Active catalog: 0aa3fe82-…

If that is not the catalog you expected, the URL is pointing at a different server or a different virtual directory — fix the URL rather than looking for a catalog selector.

After a successful connect

What fills inWhy
Shared collection and Saved search listsRead from the server, so you pick by name instead of by id. If either list is empty, those scopes fall back to typing an id by hand.
Your previous settingsScope, search term, filters and limits are restored from the last successful connect, so a repeated run is one button press.
Count matching itemsBecomes usable once there is a connection to ask.

A failed login never overwrites a working set.

Synapic saves the connection block only after the server accepts the login, so a typo in the password cannot destroy the details that worked yesterday. The stored password is protected with Windows DPAPI and can only be read by that Windows account on that machine.

Disconnecting

Disconnect appears once you are connected. It ends the session, clears the collection and saved-search lists, and disables counting. The saved connection stays in the registry, so reconnecting is one press of Connect.

When a connection fails

MessageUsual cause
Connection failed: … (a timeout or a socket error)The URL is wrong, the Daminion server is not running, or a firewall is in the way. Check the URL first: a missing scheme or a wrong virtual directory is the common case.
Connection failed: … (a 401 or "unauthorised" style error)Wrong username or password, or an account that may not use the API.
Connected, but saved searches or collections are unavailableThe login worked but those endpoints did not answer. Tagging still works; the two pickers fall back to manual ids.
Count failedThe count request was rejected or timed out. Filters still apply to the batch; the count is a preview, not a precondition.

The log pane and logs\synapic.log hold the full message for any of these.
