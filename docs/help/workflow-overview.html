The five-step workflow

One image at a time, Synapic fetches the image, asks the model for tags, and writes the tags. The five steps are the decisions you get to make before and after that loop.

Source first, then the route

Every launch opens on a start screen, and it asks one question before it asks what you want to do: which images? The source panel holds a local folder picker and the Daminion connect form, and two lights above them answer the question at a glance — green while a Daminion session is live, green while the chosen folder exists, red while either is missing. The record count for the chosen source runs on its own: on launch, after a connect, and whenever the folder, the scope or a filter changes.

The three workflow cards below stay disabled until one of those lights is green — a folder that exists, or a real connection to the Daminion server. Pick the source, then pick the route; the choice follows you into the wizard.

RouteWhat it is forSteps it shows
TaggingRun the model over a datasource and write the tagsDatasource → Engine → Process → Results
DeduplicationFind near-duplicate images and act on the extrasDatasource → Deduplication
UpscalingEnhance image resolution (the Daminion Feature enhancement utility)Datasource → Upscaling

All three routes start from the same source. Step 1 reports it read-only and owns the processing limits (how many items, and how much of each image); the source itself is changed on the start screen, next to the record count. The deduplication and upscaling routes skip the tagging steps entirely: Next goes straight to that route's step. In those routes the nav bar shows just 1 · Datasource and the route's own step.

The Home button in the nav bar returns to the start screen at any time; the route you were in is kept, so coming back and picking a card resumes where you left off. The tagging route still exposes Deduplication and Upscaling from their own tabs once you reach Results.

What happens to each image

  1. Fetch. For a folder, Synapic lists the image files it recognises (.jpg, .jpeg, .png, .tif, .tiff) — recursively if you asked for that. For Daminion, it pages through the catalog for the items your scope and filters select, and downloads an image (or a thumbnail) for each item as it reaches it.
  2. Tag. The image goes to the inference server, which returns three things in one call: a category, a list of keywords, and a description.
  3. Write. Synapic keeps the fields you ticked in Step 2 and writes them — XMP metadata in the file for a folder, or a metadata update for a Daminion item. Fields you did not tick are discarded here, not at the model.
  4. Record. The outcome is appended to the run's results: success, write failure, or an error explaining why that image could not be processed.

One call, three results.

There is no per-field choice of model or task, and no second request for the description. A single multimodal call produces everything, which is why Step 2's field checkboxes only change what gets written. See Tag fields: what gets written.

How much runs at once

Synapic keeps four images in flight during a batch: while one image is waiting for the model, another can be downloaded and a third written. Two consequences are worth knowing before you read a log or a stopwatch:

  • Throughput is not latency. Four images finishing roughly every ten seconds means one image every two or three seconds on average, while each individual image still took ten. A folder of 200 images therefore takes minutes, not seconds — and the ETA in Step 3 is computed from completed images, so it settles after the first couple.
  • A GPU changes the arithmetic. Four parallel calls share one model. On a CPU that is usually a win; on a small GPU the calls can contend, so a CUDA build does not always beat a CPU build by the factor the hardware suggests. Judge it on a batch of real images rather than one image.

What Synapic deliberately does not do

  • No cloud service. There is no hosted engine and no API key to store; the only model is the local one.
  • No review step before writing. Tags are written as the batch runs. If you want to approve things first, run against a folder or a disposable collection, then apply the same settings to the real target.
  • No automatic language translation or vocabulary control. The model writes in the language the image implies. A system prompt is how you steer that; see Prompts.
  • No undo. A metadata write replaces the previous values of the fields Synapic manages. Keep a backup of a collection before a large first run.
