Reading the log

The log is the app's account of what it did. Most support questions are answered by three lines: the one that starts a batch, the one that reports each image, and the one that ends the run.

Where the log is

WhereWhat it holds
The Log pane at the bottom of the windowThe most recent lines, scrolling as the batch runs. Includes the inference server's own error output, prefixed [sidecar:err].
logs\synapic.log, next to the executableThe current run, written as it happens. It starts empty each time the app starts.
logs\archives\The previous runs. Each app start moves the old log here, and the ten most recent archives are kept.

If the app cannot write next to the executable — a locked-down Program Files folder, for example — logs go to %LOCALAPPDATA%\Synapic\logs instead. See Logs, crashes and support.

The lines worth knowing

LineWhat it tells you
Starting batch: 42 items — writing keywords, categories and descriptionThe run began, and which of the three tag fields will be written. Read this first when fields come back missing: it names the selection that caused it. See Tag fields.
Found 128 image files in D:\photos (recursive=True)How many files the folder scan picked up, and whether subfolders were included.
Fetched 500 Daminion items (scope=collection)How many catalog items the scope and filters selected, before any tagging.
Processing: IMG_0421.jpg...An image has been taken up. Its result follows.
Result: Cat: Landscape, Kws: 7, Desc: A mountain lake at sunrise...What the model produced: the category, how many keywords, and the start of the description. If the category here looks right but your library has none, the problem is the write step, not the model.
Failed: IMG_0422.jpg — <reason>That image could not be tagged, with the reason. The image is counted as failed and recorded in Step 4.
Batch finished: 40 ok, 2 failed, 42 totalThe run's summary. These numbers are also reported in Step 4.
Progress scoring unavailable: ...Expected with the local model: the confidence and probability settings do not apply to it. Not an error. See Step 2 — Tagging Engine.

When something goes wrong

LineLikely cause
Folder not found: D:\photosThe Step 1 path does not exist on this machine, or a drive is not mounted.
Daminion client not connectedThe session lost its connection. Reconnect in Step 1 and retry the batch.
Could not download image for item 12345The catalog item could not be fetched — a permissions problem, or a file that no longer exists on the Daminion side.
Daminion returned the same ids as the previous pagePaging hit a server that ignored the offset. Synapic stops instead of looping forever; the batch covers what it fetched.
Timed out waiting for the sidecar port fileThe inference server failed to start. Its own output is in the log just above this line.
Sidecar process exited unexpectedlyThe server crashed. Restart it from the toolbar and retry; the log holds its last words.
[sidecar:err] ...The server's own error stream, passed through unchanged for exactly this purpose.

Using the log well

  • Start from the top. The batch's first line records the settings the run used, which is often the whole answer.
  • Count the result lines. If they match the summary, every image was accounted for; a mismatch usually means the run was aborted.
  • Keep the file, not the pane. The pane is a window onto the run; the file is the record. Archives from previous runs are still there after a restart, which is how you compare today's run with last week's.
  • Do not read timings from the log's order. Four images are in flight at once, so lines interleave and gaps between them measure throughput, not how long one image took. Step 3's ETA line is the honest per-image figure.

Send the log, not a screenshot.

When asking for help, attach logs\synapic.log and say which run it was. It carries the settings each batch used, so nobody has to guess at them. See Logs, crashes and support.
