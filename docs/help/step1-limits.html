How many items to process

The last row of Step 1 decides how big the batch is and how much of each image the model looks at. Both are about time, not quality.

How many items

ControlWhat it does
Max itemsThe ceiling for this run: 100 by default, raised in steps of 50. The batch stops when it has taken that many items. Setting it to 0 removes the ceiling, exactly as Process all does.
Process all (page until empty)Ignores the ceiling and keeps requesting pages of results until the server returns none. This is the switch for a catalog larger than a single API response — without it, a big catalog can look like it was fully processed when only the first page was.
Count matching itemsReports how many items the scope and filters select, so you can size the job before running it. See Scope and filters.

Order of work is the catalog's, not yours.

Items arrive in pages as the server returns them. There is no "start with the newest" option: if order matters, encode it as a scope (a saved search that sorts what you want first) rather than a limit.

How much of each image the model sees

ControlWhat it does
AI image scaleDownscales the image before tagging: 100% (default), 75%, 50% or 25%. Smaller means faster and less memory; the model still sees the whole frame, just with less detail.
Use fixed 200px thumbnail (fast)Asks Daminion for its 200-pixel thumbnail instead of the full image, which is dramatically faster on a large catalog. It overrides the scale setting.

Thumbnails trade quality for speed, and you can hear it.

At 200 pixels the model often misses fine detail: a small sign, a serial number, the difference between two similar species. It is the right setting for a first pass over a huge catalog, and the wrong setting for the run you intend to keep. If your descriptions come back vague and generic, raise the scale before changing the prompt.

Sizing a run you can actually finish

SettingUse it when
100%, folder, 100 itemsTrying the model on your own images, or tagging a curated set properly.
75% or 50%, folderOrdinary work on a machine without a GPU: a little faster, with little visible loss.
30–50%, Daminion, saved searchA big catalog where the tags will be reviewed before anyone trusts them.
200px thumbnail, Process allA first pass over tens of thousands of items, to triage what deserves a full run.

You can run the same items twice.

Tags are written, not merged: a second run over the same items replaces the keywords, category and description that Synapic manages. That makes "rough pass now, proper pass later" a viable plan — just be aware that the second run overwrites the first, rather than adding to it.
