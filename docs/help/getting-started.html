Getting started with Synapic

This topic is the long version of your first five minutes: what Synapic actually does, why it asks you to build a server before it will tag anything, and what a first batch feels like. The tick-list version is the setup guide; this is the explanation behind it.

The idea, in one page

A vision-language model looks at a picture and describes it. Synapic wraps a library workflow around that one skill: for every image it collects three answers — a category, a set of keywords, and a description — and writes them where your library keeps its words.

Two ideas explain almost everything the app does afterwards:

IdeaWhat it means in practice
It runs on this machineThe model is downloaded once (about 860 MB) and executed locally. No account, no API key, no per-image cost, and your images are never uploaded. It is also why the first run is slower than every run after it.
The engine is a separate programThe inference server (also called the sidecar) holds the model and answers one request per image. Synapic starts it, talks to it over a local port, and stops it when the app closes. It is the one part you have to build or download before anything can be tagged.

Where the words go is your choice, and it is the first thing the app asks:

  • A folder on disk — the tags are written into the image files themselves, as XMP metadata, so a tagged folder travels: copy it to a machine without Synapic and the words come with the images.
  • Your Daminion catalog — the tags are written back through the Daminion API, so the catalog stays the source of truth and the metadata lives where your colleagues already look for it.

One call produces all three fields.

There is no second request for the description and no per-field model. Step 2's Tag fields checkboxes decide what gets written, not what the model is asked — which is the answer to the most common "why are my keywords there but my description missing?" question. See Tag fields: what gets written.

What you see when it opens

Synapic is one window: a toolbar for the server at the top, the source panel and the three routes in the middle, and a live log along the bottom.

The order of that middle section is deliberate. A run means nothing until you know which images it covers, so the source panel comes first, and it answers that question twice over: once in words you choose (a folder, or a Daminion login plus scope), and once at a glance, in two source lights.

LightGreen meansRed means
DaminionA session is live; the line beside it names the server URL.Nobody is signed in. Credentials typed into the form do not count until the server accepts them.
FolderThe folder exists; the line beside it names it, and says when subfolders are included.No folder selected yet, or the typed path does not exist.

Under the lights the panel shows the record count — how many images the current source and scope select. It keeps itself current: at launch, after a connect, and every time the folder, the scope or a filter changes. Nothing needs pressing; the Recount button is only there for the case where the catalog changed underneath you.

Only then do the three routes matter, and they stay disabled until one of the lights is green — so a workflow is never entered without knowing what it would work on:

RouteWhat it is for
TaggingRun the model over the source and write the tags. Four steps: Datasource, Engine, Process, Results.
DeduplicationFind near-duplicate images — local folder or catalog scope — and tag, move or delete the extras.
UpscalingRaise image resolution, with AI (Swin2SR) or fast Lanczos resampling, over the same source.

Install

  1. Run Synapic-Setup-win-x64.exe. Windows asks for administrator rights, because the app installs under C:\Program Files\Synapic.
  2. If the .NET 10 Desktop Runtime is missing, the installer takes care of it at the Ready step — silently, from the copy bundled in the setup or by downloading the official installer. You may see a restart prompt afterwards.
  3. Choose whether you want a desktop icon, then finish. The installer offers to launch Synapic for you.

For unattended installs and for the other platforms, see Installing and upgrading.

Your first run, end to end

If this is a fresh install, the first thing you will notice is that the wizard is greyed out and a panel says Inference sidecar required. That is expected, and it is the only part that takes real time:

  1. Get an inference server. In the panel, press Download on the CPU row to fetch the prebuilt executable, or Build sidecar to compile it from source — that first build downloads a private Python and the packages the model needs, so expect minutes, not seconds. Full detail: Build the inference server.
  2. Let the server start. Synapic launches the server as soon as one exists, and the status dot turns green with Server running (port …). The very first launch is slow — up to a couple of minutes — because the model is unpacked and loaded.
  3. Choose the images. In the source panel, either point at a folder on disk or connect to Daminion. Watch the matching light turn green and the record count appear; that pair is your confirmation that the run will see what you think it will. For a first test, a small folder is the kindest choice.
  4. Run the batch. Pick Tagging, then go to Step 3 — Process and press Start Processing. The first image also triggers the model download (about 860 MB) if the model has never been used on this machine.
  5. Review. Step 4 — Results lists what happened to every image, and Verify Daminion Writes re-reads a Daminion catalog to confirm the tags really landed.

What a batch is doing, image by image

Understanding the loop explains the timings, the log and the one thing you cannot do (go back):

  1. Fetch. For a folder, the files are listed; for Daminion, the items your scope and filters select are paged from the catalog and each image (or a thumbnail) is downloaded as it is reached.
  2. Tag. The image goes to the inference server, which returns the category, keywords and description in one call.
  3. Write. The fields you ticked in Step 2 are written — XMP into the file, or a metadata update for a Daminion item. Because the write replaces what Synapic manages, there is no undo; run a first batch on copies if that matters.
  4. Record. The outcome is appended to the run's results: success, write failure, or an error explaining why that image could not be processed.

Four images move through that loop at once, so a batch is never as slow as one image times the count — see the workflow for how throughput and latency differ.

What the first run costs you in time

StageWhat happensRoughly
Building the inference serverDownloads a standalone Python and the inference packages, then packages them into one executableMinutes to tens of minutes, once
First server startUnpacks the executable and imports the runtimeUp to two minutes, every launch
Model downloadAbout 860 MB, once per machineDepends on the connection
Model loadWeights into memory before the first tagTens of seconds on CPU
Each image after thatOne model call plus a metadata writeAround ten seconds on CPU; less on a GPU

The second run of the same folder is dramatically faster than the first, and the second batch of the same session faster still: the model is already in memory and the server process is already running.

A safe first batch

To see what the model produces without committing anything, tag a copy of a dozen images in a folder:

  1. The source panel: choose Local Folder, point at the copy, and leave Include subfolders off. The folder light turns green and the count reports roughly a dozen files.
  2. Step 2: leave the defaults. The three Tag fields boxes are ticked, so all three results are written into the files' XMP metadata.
  3. Step 3: Start Processing, then read the log as it scrolls. A line per image reports the category, the number of keywords, and the start of the description.
  4. Step 4: check the rows, then look at one of the files in your own image viewer or in Daminion to see the metadata.

What Synapic will not do for you

Knowing the edges saves a lot of second-guessing:

  • There is no cloud service and no account. If the app wanted to upload your images, this help would have a section about quotas. It does not.
  • There is no undo. A metadata write replaces the previous values of the fields Synapic manages. Keep a backup of a collection before a large first run, and rehearse on copies.
  • There is no vocabulary control and no translation. The model writes in the language the image implies, with the words it knows. A system prompt is how you steer that — see Prompts.
  • There is no review step before writing. Tags are written as the batch runs. If you want to approve them first, run against a folder or a disposable collection and then apply the same settings to the real target.
  • There is no curation. The model does not know which of two similar shots you meant to keep, and it cannot read your catalog's rules. That judgement is still yours; the tool is there to make it cheap.
