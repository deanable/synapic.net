Step 2 — Tagging Engine

Step 2 is where the interesting decisions live: which model runs, what you ask it for, and which of its answers are allowed to reach your images. The defaults are deliberately sensible; you can tag a whole library without changing anything here.

The model

Synapic ships with one family of models — a vision-language model that answers in the three fields this app needs. The list at the top of the step shows what is already in the local model cache, with each model's task, size, and a ✓ downloaded marker.

ControlWhat it does
Refresh local modelsAsks the inference server what models are in the cache. Run it after you download one elsewhere.
Model listPick a cached model. The grey text is its task and size.
Download model…Fetches the selected model into the cache before you run a batch, so the download does not happen in the middle of one.
Model id boxType any compatible model repository id, for example LiquidAI/LFM2.5-VL-450M. This is the id sent to the inference server.

The default is chosen for a machine like yours.

The shipped default (LiquidAI/LFM2.5-VL-450M) is a small multimodal model: quick enough on a laptop CPU to tag thousands of images overnight, and accurate enough to be useful. The task line beside the model list reads Category + Keywords + Description (multimodal) because there is no per-field choice: one call produces all three.

Device

DeviceNotes
CPUThe default and always correct. Slower, but needs nothing special and cannot fail for driver reasons.
CUDARequires the CUDA build of the inference server (see Build the inference server) and an NVIDIA driver. Much faster when both are present.
MPSApple silicon GPU acceleration, on macOS builds.

If the device does not match the server you have, requests fail with an error in the log. When in doubt choose CPU; it is the only device that needs no counterpart in the server build.

Scoring controls

Four controls on this row come from the general-purpose tagging pipeline: Confidence threshold, Probability mode, Prob. threshold and Candidate labels.

They do not constrain the local model.

The confidence and probability machinery applies to a different kind of model (classification and zero-shot label scoring). A vision-language model answers in prose, so those settings are ignored, and the log may say that progress scoring is unavailable — which is expected, not an error. Leave them at their defaults unless you are deliberately experimenting with candidates: no value here will make a category wrong, or right.

The three things that shape the output

ControlEffect
System promptContext prepended to every request: tone, vocabulary, language, domain. Optional, and remembered across runs.
Tag instructionWhat the model is asked to produce. Blank means the built-in instruction, which is the version that reliably returns all three fields.
Tag fieldsWhich of the three returned fields are written. This one changes what lands in your library more than any other setting on the page.

Read the tag fields page before your first big run.

A single unticked box here is the most common reason a library ends up with keywords only, and the app will not interrupt you about it — it writes what you asked, and logs success. Tag fields: what gets written takes two minutes and can save a batch.
